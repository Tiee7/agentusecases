# Agent 商业案例研究

收集和分析 AI Agent 的真实商业案例，帮助产品负责人、创业者和经营团队判断：**谁需要它、谁会付钱、怎样交付，以及是否值得投入。**

这里不只整理工具介绍或成功故事。每篇深研从原始案例出发，核查公开证据，拆解客户需求、商业机制、获客与交付成本，并明确哪些结论得到支持、哪些仍需验证。

截至 2026-10-21，仓库登记 **1,492 个案例**，其中 **78 篇已完成商业深研**、**115 篇简要分析**，分别统计。登记不代表已经研究；深研见[研究总索引](INDEX.md)，简报见[简要分析索引](research/brief/INDEX.md)。

正文与翻译覆盖见[档案说明](registry/ARCHIVES.md)：1,492 条已取得的案例正文持久保存在仓库，171 条有完整中文译文，其余译文待补充。

## 从哪里开始

| 想了解什么 | 阅读入口 |
|---|---|
| 找已完成的研究，比较结论与评分 | [商业深研总索引](INDEX.md) |
| 浏览全部案例，区分已完成与待研究 | [完整案例目录](registry/CATALOG.md) |
| 阅读单个案例的完整商业分析 | [独立报告](reports/) |
| 获取可用于筛选、比较或二次分析的数据 | [结构化研究记录](research/)与[案例登记表](registry/cases.json) |
| 检查引用来源、读取时间与内容哈希 | 各报告末尾来源链接及[来源读取凭据](research/evidence/) |
| 理解判断依据与质量要求 | [研究标准](RESEARCH_STANDARD.md) |

例如，[EU261 航空拒赔申诉代理](reports/dispute-an-airline-s-eu261-delay-compensation-rejection.md)研究了“获批赔偿”的案例叙述与可经营服务之间的距离，比较免费投诉渠道和收费代索赔服务，并测算人工审核、获客与回款率对利润的影响。报告给出“仅建议受控试点”的判断，没有将案例声称的赔偿额当作服务商收入。

## 每篇研究回答什么

- **客户与需求**：真实使用者、付款人和预算归属是谁？痛点发生多频繁，现有做法有什么成本？
- **商业机制**：交付什么价值，按什么单位收费？收入、赔偿、退款和时间节省是否被混淆？
- **获客与交付**：客户从哪里来，为什么信任服务？从输入到结果有哪些步骤，哪些需要人工审核或接管？
- **成本与利润**：除模型费用之外，人工、数据、第三方服务、维护和获客成本如何影响收益？至少给出两种可复算的单位经济情景。
- **竞争与可复制性**：免费渠道、现有软件、人工服务或平台功能能否替代？是否存在可积累的流程、数据或分发优势？
- **经营决策**：下一步验证什么，达到什么条件继续，出现什么情况停止投入？

每个案例使用固定 ID，对应一份 `reports/<id>.md` 报告、一份 `research/<id>.json` 结构化记录，以及一份 `research/evidence/<id>.json` 来源凭据，便于从总索引追溯到具体判断和证据。

## 如何形成判断

研究以案例页面为线索，优先追到原始报道、官网、公开代码、文档、定价和条款，再结合竞争方案与独立资料检验初始判断。来源链接和实际读取凭据随报告保存；读取成功只证明取得了内容，不保证来源的说法正确。

完成的深研至少包含 6 份实际读取来源、3 个发布域名、2 份一手资料和 8 条可追溯事实。报告明确区分**已核验事实、作者自述、教学或模拟数字、研究者情景假设与有限实测**。访问受限、缺少到账凭证、没有真实付费客户或未运行项目等情况会直接写入限制，不以搜索摘要代替原文，也不把代码阅读当作生产验证。

真实用户评价是辅助证据：检查直接使用者与同类工作流体验的区别，注意宣传和自选样本偏差。缺少可核验反馈时，独立反馈信号记为 0，含义是缺少证据，而不是用户给了差评。

| 商业评分维度 | 权重 |
|---|---:|
| 付费需求 | 20% |
| 业务价值与效果证据 | 20% |
| 单位经济与利润 | 20% |
| 获客与市场进入 | 15% |
| 竞争壁垒 | 10% |
| 交付与经营风险 | 10% |
| 独立用户反馈信号 | 5% |

各维度按 0–5 分加权为百分制，用于比较商业投入优先级，不是模型性能、用户星级或收益保证。每篇报告给出以下判断之一，并说明理由与止损条件：**建议投入客户验证／仅建议受控试点／适合内部效率工具／不建议商业投入**。

## 使用与复核

可直接阅读 Markdown 报告；需要批量比较时，使用结构化 JSON 和稳定案例 ID。历史批次汇总或介绍型草稿不等于已完成深研；完成状态以版本 2 记录中的 `status: completed` 及总索引为准。

仓库同时提供[只读网页阅读版](site/README.md)，支持跨设备阅读、搜索筛选、文章目录及来源跳转。

研究流程的本地校验使用 Python 3.12+ 和标准库，无需第三方依赖：

```sh
python -m unittest discover -s tests -q
```

研究贡献者可参考[单案例研究流程](tasks/research-one-case.md)、[结构化模板](research-business-template.json)和[维护说明](tasks/maintenance.md)。发布前需检查来源、引用、数字与案例身份，并确保报告、记录和索引对应一致。

## 自用价值与动手试用

研究同时保留商业评分与独立的高/中/低/待核实自用价值；阅读站可分别筛选。报告说明人群、用途、收益、成本、频率及风险，试用区提供可复制文本、出处、作者标识、准备条件、工具与预期结果。2026-10-15首次回填的21篇基于已有证据，当时未结构化收集源站模板；后续收录状态以source_trial为准；中英文模板均明确为我们编写、未实测。旧记录没有这些字段仍可阅读并显示待核实。扩展约束见 [结构化schema](schemas/personal-use.schema.json)。Wanted不变；两路研究各自串行，独立分支验证、推送和回读完成后即可继续，无额外冷却；main 串行整合，网站验收独立进行。

源站试用模板现在从公开SSR/限定DOM结构提取，保存建议工具、来源、观测时间及可用状态；与案例作者实际agent和提示词分开。爬虫→SQLite→registry→research→阅读站保持同一文本，源站模板优先、自编模板补充。未观测不等于源站没有模板；本次修正说明见[源站模板验证记录](site/docs/source-trial-verification.md)。

阅读站的单篇先展示案例原文及已完成的中文译文，再列相关方法与来源，最后展示我们的分析；区分源站叙述、作者说明、媒体转述与原帖未读取。独立daily爬虫批量更新目录，逐案深研读取最近快照，独立分支完成验证、推送和回读后即可继续，无额外冷却。当前调度和冲突处理见[任务流程](tasks/hourly-business-research.md)。
